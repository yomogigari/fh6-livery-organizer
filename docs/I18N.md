# 国際化（i18n）

Livery Organizer for FH6 では、Python標準ライブラリだけで動作する小規模な言語リソース層を使用します。

## 現在の開発範囲（v0.4.58-r02）

- 日本語（`ja`）を既定言語およびフォールバック言語とします。
- 英語（`en`）は、国際化基盤の初期確認としてメイン画面の一部とCLIヘルプに対応します。
- アプリケーションコードから翻訳文字列を取得する場合は、`tr(key, **values)` を使用します。
- 言語設定は `settings.json` の `language` として保存できる基盤を用意しますが、言語選択UIは後続revisionで実装します。
- 開発・確認用途に限り、環境変数 `FH6_ORGANIZER_LANG=en` で保存済み設定を一時的に上書きできます。この値は `settings.json` へ保存しません。
- 詳細ダイアログ、実行前チェック結果本文、生成HTMLレポートは、**r02ではまだ完全には国際化しません**。後続revisionで順次対応し、それまでは日本語表示を維持します。
- 言語選択UIも、r02では意図的に実装対象外とします。

## 言語リソースの配置

```text
src/organizer/
├─ i18n.py
└─ locales/
   ├─ __init__.py
   ├─ ja.py
   └─ en.py
```

## 国際化ルール

1. 翻訳後の表示文字列を、設定・保存データなどの永続キーとして使用しません。
2. Liveryタイトル、作成者名、メモ、タグなど、利用者または元データ由来の内容は翻訳しません。
3. 車両名・メーカー名などの元データはそのまま保持し、周辺のUIラベルだけを翻訳対象とします。
4. 日本語辞書と英語辞書は、常に同じ翻訳キーを持つようにします。
5. `{path}` や `{version}` などの書式プレースホルダーは、言語間で完全に一致させます。
6. 未対応・不正な言語指定があった場合は、日本語へフォールバックします。
7. Python版とNuitkaによるWindows EXE版の構成を単純に保つため、国際化処理には外部Pythonパッケージを追加しません。
8. 日本語と英語で文字列長が異なることを前提にし、新規UIでは可能な限り固定幅を避けます。
9. 将来ほかの言語を追加する際も、日本語・英語と同じキー体系を使用します。

## テスト

リポジトリ直下で以下を実行します。

```powershell
uv run python -m unittest tests.test_i18n
```

このテストでは、主に以下を確認します。

- 日本語・英語辞書の翻訳キーが一致していること
- 書式プレースホルダーが言語間で一致していること
- `ja-JP`、`en-US` などの言語指定が正規化されること
- 未対応言語が日本語へフォールバックすること
- 基本的な `tr()` 呼び出しが正常に動作すること

## 英語表示の開発用プレビュー

PowerShellでは以下のように一時的に英語表示を確認できます。

```powershell
$env:FH6_ORGANIZER_LANG = "en"
uv run src\organizer\livery-organizer-for-fh6.py
Remove-Item Env:FH6_ORGANIZER_LANG
```

`FH6_ORGANIZER_LANG` は開発・確認用です。
この方法で選択した言語は保存されないため、通常起動時の利用者設定には影響しません。
