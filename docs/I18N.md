# Livery Organizer for FH6 国際化方針

## 基本方針

- フォールバック言語は日本語 (`ja`) とする。
- 最低限の対応言語は日本語 (`ja`) と英語 (`en`) とする。
- UI文字列は `tr("キー")` 経由で取得し、ソースへ表示文言を直接埋め込まない。
- `ja.py` と `en.py` の翻訳キー集合は常に一致させる。
- `{path}` や `{count}` などの書式プレースホルダーも言語間で一致させる。
- 未対応言語や不正な言語指定は日本語へフォールバックする。
- 外部Pythonパッケージは追加しない。

## 言語設定

- `settings.json` の `language` に利用者の選択を保存する。
- メイン画面の言語選択は次回起動時に反映する。
- 開発・テスト時は `FH6_ORGANIZER_LANG=en` のように環境変数で一時上書きできる。
- 環境変数による一時上書きは保存済み設定を書き換えない。

## 表示とパス

- 日本語UIでは従来どおりWindowsパスを `¥` 区切りで表示する。
- 英語UIではWindows本来の `\` 区切りで表示する。
- `JSON / CSV` のような一般文字列中の `/` はパス区切りとして変換しない。
- 英語化で長くなる説明文は折り返し可能なレイアウトを優先する。

生成HTML / Excel内のUI文字列はr03では対象外とし、次revision以降で別途国際化する。

## 翻訳しないもの

- 利用者が保存したLiveryタイトル、説明、作成者名
- 内部識別子、Car ID、Livery ID
- FH6アセット由来の内部名
- 公式車種データとして保持する固有名詞そのもの

## テスト

`tests/test_i18n.py` で次を確認する。

- 日本語 / 英語の翻訳キー一致
- 書式プレースホルダー一致
- 言語コード正規化
- 日本語フォールバック
- パス表示切替
- 実行前チェック / 出力構成 / サポート情報の日本語・英語切替
- `App` クラス内に日本語固定の利用者向け文字列が残っていないこと
