# Livery Organizer for FH6 国際化方針

## 基本方針

- フォールバック言語は日本語 (`ja`) とする。
- 最低限の対応言語は日本語 (`ja`) と英語 (`en`) とする。
- デスクトップGUI / CLIのUI文字列は `tr("キー")` 経由で取得し、ソースへ表示文言を直接埋め込まない。
- `ja.py` と `en.py` の翻訳キー集合は常に一致させる。
- `{path}` や `{count}` などの書式プレースホルダーも言語間で一致させる。
- 未対応言語や不正な言語指定は日本語へフォールバックする。
- 外部Pythonパッケージは追加しない。

## 言語設定

- `settings.json` の `language` に利用者の選択を保存する。
- メイン画面の言語選択は次回起動時に反映する。
- 開発・テスト時は `FH6_ORGANIZER_LANG=en` のように環境変数で一時上書きできる。
- 環境変数による一時上書きは保存済み設定を書き換えない。
- 生成HTML / Excelはレポート生成時点のOrganizer言語を使用する。

## 表示とパス

- 日本語UIでは従来どおりWindowsパスを `¥` 区切りで表示する。
- 英語UIではWindows本来の `\` 区切りで表示する。
- `JSON / CSV` のような一般文字列中の `/` はパス区切りとして変換しない。
- 英語化で長くなる説明文は折り返し可能なレイアウトを優先する。

### 生成HTMLで利用者データを翻訳しないための境界

レポート用i18n層はOrganizer自身のUIテキストだけを対象とする。

以下は英語レポートでも原文を保持する。

- Liveryタイトル
- Livery説明
- 作成者名
- 車名 / メーカー / モデルなどのデータ値
- Livery ID / Car ID / fingerprintなどの識別情報
- 利用者が入力したタグ / メモ

カードや比較表示の利用者データ領域は翻訳対象から除外する。UI側で件数や状態がJavaScriptによって後から変わる部分は、限定した動的ルールで翻訳する。

### r04 実データHTMLで追加した監査項目

英語生成HTMLは、初期DOMだけでなく実際の操作後にJavaScriptが作り直す文言も監査する。

- `optgroup` の `label`、`data-closed-label`、`data-base-label` など、通常の `title` / `aria-label` / `placeholder` 以外の表示用属性も対象とする。
- 「レポート情報を閉じる」のように、パネル開閉後に変化するボタン名も対象とする。
- FH6マイデザインの実件数、列数、再DL完全一致の組数 / 件数など、実データによって数値が変わる文言は固定値ではなく動的規則で翻訳する。
- Navigatorのカード選択後に生成される「最終実スロット / 初期位置」と、類似比較を開いた後に生成される「判定理由 / 件数 / 取得日時順」の概要も状態遷移後に監査する。
- Diagnosticsは実行後のチェック名、概要、問題詳細まで監査する。
- CSS疑似要素 (`::before` / `::after`) の表示文字列も監査する。
- 比較画面へ複製した車名、タイトル、説明、作成者などは専用クラスで利用者データ領域として保護し、UI語と同じ文字列であっても翻訳しない。
- テスト用データには、`お気に入り` / `作成者` / `メーカー` のようにUI語と衝突する日本語を意図的に含め、利用者データが保持されることを確認する。

開発側のブラウザ監査では、Report Information、More Actions、Diagnostics、FH6 My Designs、Navigator設定、再DL重複整理、任意選択比較、タグ管理などを実際に開いた後のDOMを確認する。

### デスクトップGUIのログ欄

r04実機確認で、従来のウィンドウ高さではログ欄が実質1行程度まで圧縮されるケースを確認した。メインウィンドウの既定高さを少し広げ、ログ欄は約3行を常時確認できるサイズを基準とする。

### r04 edge case 最終監査

実データHTMLの通常操作で翻訳漏れが解消した後、通常は発生しにくい欠損データ / 旧データ / 例外系も追加で確認する。

- メーカー、車両アセット、タイトル、作成者情報が欠損した場合のシステム生成フォールバックは、利用者データ保護領域の中でも生成時点の言語で直接出力する。
- ペイント0件 / 作成者0件のレポートでも、空状態メッセージを生成時点の言語で直接出力する。
- 旧形式または不正な新規判定基準 / バックアップ日時では、`日時不明` 相当の表示を言語別フォールバックへ切り替える。
- 新規 / 消滅比較で車種名やタイトルが欠損した旧データも、Organizer生成の `Unknown vehicle` / `No title` などを使用し、利用者データそのものとは区別する。
- JavaScript例外時の `Unknown error` / `Promise error` も生成時点の言語で定義し、エラー時だけ日本語へ戻らないようにする。
- 英語レポートの日時 / 数値 / 文字列比較は `en-US`、日本語レポートは `ja-JP` をレポート用localeとして使用する。JavaScript内で `ja-JP` / `ja` を固定しない。
- これらのフォールバックは生成側で直接ローカライズし、レポート用i18n層にも安全網として同じ対応を保持する。

自動テストでは、通常データに加えてメタデータ欠損、0件レポート、旧 / 不正日時、JavaScript例外用フォールバック、レポートlocaleの切替も確認する。

## v0.4.58-r05 — 疑似ローカライズ / 長文レイアウト耐性

実際の第三言語を追加する前に、英語UIを意図的に長文化する開発専用の疑似ロケール `qps` を追加する。

- `qps` は利用者向けの対応言語ではない。通常の言語選択には `日本語` / `English` だけを表示する。
- 開発時だけ `FH6_ORGANIZER_LANG=qps` で有効化する。`settings.json` に `qps` を手動記入しても通常起動では日本語へ戻す。
- 疑似文字列は英語を基準にアクセント付き文字へ変換し、約30〜50%の余白文字を追加して `⟦ ... ⟧` で囲む。
- `{path}` / `{count}` などの書式フィールドは疑似変換しない。埋め込まれるパス、件数、車名などの値を壊さない。
- 未対応の実言語（例: `de-DE`）が自動的に `qps` になることはなく、従来どおり日本語へフォールバックする。
- 生成HTMLでも `lang="qps"` を開発時だけ使用し、日時 / 数値ロケールは英語系の `en-US` を使用する。
- Liveryタイトル、説明、作成者、車名などの利用者データを疑似翻訳する目的ではなく、Organizer自身のUIが長くなった場合のレイアウト耐性を検証する。

### デスクトップGUIで追加した耐性

疑似ローカライズで実際に要求サイズを測定し、固定幅 / 固定高だけに依存していた箇所を調整する。

- メイン説明と設定保存先表示は横幅内で折り返す。
- 上部の主要操作ボタンは、必要幅が大きい言語では自動的に2行へ配置する。日本語 / 英語で1行に収まる場合は従来配置を維持する。
- メインウィンドウは既定 `1000×840` を基準としつつ、翻訳が長く必要高さが増えた場合だけ画面内で必要高さへ拡張する。
- ログ欄は長い言語でも約3行を確保することを基準とする。
- Quick Start Guideは固定650px高だけにせず、翻訳後の要求高さが大きい場合は必要高さへ拡張する。
- `tests/gui_pseudo_r05.py` では1920×1080相当の仮想画面でメインGUI、Quick Start Guide、Environment / Support Informationを実際に構築し、横方向の文字切れと要求サイズ超過を確認する。

### 生成HTMLで追加した耐性

疑似ローカライズでは英訳辞書のUI文字列を長文化してブラウザ上で実行する。

- 中幅画面の「車種整理」操作バーは折り返し可能にし、長いボタン名でページ全体が横へ伸びないようにする。
- 541〜900pxのツールバーではボタン文字列の折り返しを許可し、固定的な `white-space: nowrap` による文字切れを防ぐ。
- 開発側ブラウザ監査では 1440px / 1024px / 800px / 390px で疑似ローカライズHTMLを実行し、ページ全体の横overflowと主要button / selectの文字切れがないことを確認する。
- Filter、Report Information、More Actions、Help、FH6 My Designs、FH6移動対象選択など状態遷移後も同じ横overflow監査を行う。

この `qps` は翻訳品質を評価する言語ではなく、将来ドイツ語・フランス語など文字列が長くなる言語を追加する前にレイアウト上の弱点を検出するためのテスト機能として扱う。

## v0.4.58-r10: 国際化ファイル構成

言語関連ファイルを `src/organizer/locales/` と `i18n.py` に集約しました。

- `locales/ja.py`: 日本語UI文字列と日本語ロケール情報
- `locales/en.py`: 英語UI文字列、生成HTML用の英訳辞書・属性辞書・動的置換リソース
- `i18n.py`: 言語選択、`tr()`、疑似ローカライズ、生成HTMLの翻訳スクリプト生成など言語非依存の共通処理

従来の `src/organizer/report_i18n.py` は廃止しました。生成HTMLは引き続き日本語を基準HTMLとして生成し、英語/qps時だけ `i18n.py` が `locales/en.py` のリソースから翻訳層を埋め込みます。Liveryタイトル、説明、作成者、車名などの利用者データを翻訳しない方針は変更していません。

### `locales/en.py` の保守書式

英語ロケールの翻訳辞書は、人が直接確認・修正しやすいよう **1エントリを1物理行**で記述します。長い英訳もPythonの暗黙文字列連結で数語ずつ複数行へ分割せず、改行を含む表示文字列は `\n` を使ってソース上では1行に保ちます。テストでこの書式を監査し、自動整形などによる再分割を検出します。
