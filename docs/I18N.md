# Livery Organizer for FH6 国際化方針

## 基本方針

- フォールバック言語は日本語 (`ja`) とする。
- 最低限の対応言語は日本語 (`ja`) と英語 (`en`) とする。
- デスクトップGUI / CLIのUI文字列は `tr("キー")` 経由で取得し、ソースへ表示文言を直接埋め込まない。
- `ja.py` と `en.py` の翻訳キー集合は常に一致させる。
- `{path}` や `{count}` などの書式プレースホルダーも言語間で一致させる。
- 未対応言語や不正な言語指定は日本語へフォールバックする。
- 外部Pythonパッケージは追加しない。

## 言語設定

- `settings.json` の `language` に利用者の選択を保存する。
- メイン画面の言語選択は次回起動時に反映する。
- 開発・テスト時は `FH6_ORGANIZER_LANG=en` のように環境変数で一時上書きできる。
- 環境変数による一時上書きは保存済み設定を書き換えない。
- 生成HTMLはレポート生成時点のOrganizer言語を使用する。

## 表示とパス

- 日本語UIでは従来どおりWindowsパスを `¥` 区切りで表示する。
- 英語UIではWindows本来の `\` 区切りで表示する。
- `JSON / CSV` のような一般文字列中の `/` はパス区切りとして変換しない。
- 英語化で長くなる説明文は折り返し可能なレイアウトを優先する。

## v0.4.58-r04 の範囲

生成HTMLの日本語 / 英語対応を追加する。

- HTMLの `lang="ja"` / `lang="en"` を生成時のOrganizer言語に合わせる。
- ヘッダー、統計、検索、絞り込み、並び替え、整理、バックアップ、FH6マイデザイン、Bridge連携、Help、各モーダルを英語化する。
- JavaScript実行後に生成・更新されるステータスや「動作診断」の結果も英語化する。
- `title` / `aria-label` / `placeholder` も英語化する。
- CSS疑似要素で表示する「設定を開く / 閉じる」「移動対象」も英語表示へ切り替える。
- 英語レポートでは、生成HTML内へ自己完結したレポート用i18n層を埋め込む。外部JavaScriptファイルや外部ライブラリは必要としない。
- 日本語レポートではレポート用英語変換層を埋め込まず、r03までの表示を維持する。

### 生成HTMLで利用者データを翻訳しないための境界

レポート用i18n層はOrganizer自身のUIテキストだけを対象とする。

以下は英語レポートでも原文を保持する。

- Liveryタイトル
- Livery説明
- 作成者名
- 車名 / メーカー / モデルなどのデータ値
- Livery ID / Car ID / fingerprintなどの識別情報
- 利用者が入力したタグ / メモ

カードや比較表示の利用者データ領域は翻訳対象から除外する。UI側で件数や状態がJavaScriptによって後から変わる部分は、限定した動的ルールで翻訳する。

## 翻訳しないもの

- 利用者が保存したLiveryタイトル、説明、作成者名
- 内部識別子、Car ID、Livery ID
- FH6アセット由来の内部名
- 公式車種データとして保持する固有名詞そのもの

- 日本語 / 英語の翻訳キー一致
- 書式プレースホルダー一致
- 言語コード正規化
- 日本語フォールバック
- パス表示切替
- 実行前チェック / 出力構成 / サポート情報の日本語・英語切替

- 英語生成HTMLが `lang="en"` となり、自己完結したレポート用i18n層を含むこと
- 日本語生成HTMLでは英語変換層を含まないこと
- レポート用i18n層に利用者データ保護処理が存在すること

### r04 実データHTMLで追加した監査項目

英語生成HTMLは、初期DOMだけでなく実際の操作後にJavaScriptが作り直す文言も監査する。

- `optgroup` の `label`、`data-closed-label`、`data-base-label` など、通常の `title` / `aria-label` / `placeholder` 以外の表示用属性も対象とする。
- 「レポート情報を閉じる」のように、パネル開閉後に変化するボタン名も対象とする。
- FH6マイデザインの実件数、列数、再DL完全一致の組数 / 件数など、実データによって数値が変わる文言は固定値ではなく動的規則で翻訳する。
- Navigatorのカード選択後に生成される「最終実スロット / 初期位置」と、類似比較を開いた後に生成される「判定理由 / 件数 / 取得日時順」の概要も状態遷移後に監査する。
- Diagnosticsは実行後のチェック名、概要、問題詳細まで監査する。
- CSS疑似要素 (`::before` / `::after`) の表示文字列も監査する。
- 比較画面へ複製した車名、タイトル、説明、作成者などは専用クラスで利用者データ領域として保護し、UI語と同じ文字列であっても翻訳しない。
- テスト用データには、`お気に入り` / `作成者` / `メーカー` のようにUI語と衝突する日本語を意図的に含め、利用者データが保持されることを確認する。

開発側のブラウザ監査では、Report Information、More Actions、Diagnostics、FH6 My Designs、Navigator設定、再DL重複整理、任意選択比較、タグ管理などを実際に開いた後のDOMを確認する。

### デスクトップGUIのログ欄

r04実機確認で、従来のウィンドウ高さではログ欄が実質1行程度まで圧縮されるケースを確認した。メインウィンドウの既定高さを少し広げ、ログ欄は約3行を常時確認できるサイズを基準とする。

### r04 edge case 最終監査

実データHTMLの通常操作で翻訳漏れが解消した後、通常は発生しにくい欠損データ / 旧データ / 例外系も追加で確認する。

- メーカー、車両アセット、タイトル、作成者情報が欠損した場合のシステム生成フォールバックは、利用者データ保護領域の中でも生成時点の言語で直接出力する。
- ペイント0件 / 作成者0件のレポートでも、空状態メッセージを生成時点の言語で直接出力する。
- 旧形式または不正な新規判定基準 / バックアップ日時では、`日時不明` 相当の表示を言語別フォールバックへ切り替える。
- 新規 / 消滅比較で車種名やタイトルが欠損した旧データも、Organizer生成の `Unknown vehicle` / `No title` などを使用し、利用者データそのものとは区別する。
- JavaScript例外時の `Unknown error` / `Promise error` も生成時点の言語で定義し、エラー時だけ日本語へ戻らないようにする。
- 英語レポートの日時 / 数値 / 文字列比較は `en-US`、日本語レポートは `ja-JP` をレポート用localeとして使用する。JavaScript内で `ja-JP` / `ja` を固定しない。
- これらのフォールバックは生成側で直接ローカライズし、レポート用i18n層にも安全網として同じ対応を保持する。

自動テストでは、通常データに加えてメタデータ欠損、0件レポート、旧 / 不正日時、JavaScript例外用フォールバック、レポートlocaleの切替も確認する。
